# Nástroje pro vytváření bitových kopií

- **Windows ADK** (Assessment and Deployment Kit) pro Windows 11
  - Aktuálně ADK 10.1.26100.2454 (prosinec 2024) – Windows 11 24H2/25H2, Windows Server 2022/2025
  - **Windows PE add-on** je samostatný balík, verze musí odpovídat ADK
- **DISM** (Deployment Image Servicing and Management)
  - Správa (vytváření, úprava, nasazování) bitových kopií – `.wim`, `.esd`, `.ffu`, `.vhd(x)`
  - Součást Windows i ADK; PowerShell modul `Dism` (`Get-WindowsImage`, `Mount-WindowsImage`, …)
- **Sysprep** (System Preparation)
  - Příprava instalace na zachycení (*capture*); součást každé instalace Windows, ne ADK
- **Copype** a **MakeWinPEMedia**
  - Příprava předinstalačního prostředí Windows PE (z WinPE add-onu)
- Dále v ADK: **Windows SIM** (soubory odpovědí), **USMT**, **Windows Configuration Designer**, VAMT
- Historie: **WAIK** (Windows 7) → Windows ADK (Windows 8+); **MDT** (build 8456) je od roku 2025 vyřazen

# Sysprep

- Nástroj pro **přípravu instalace** systému Windows na zachycení (*capture*) nebo doručení uživateli
- Odstraňuje **informace unikátní pro počítač** (SID, ovladače, protokoly, …)
- **Oprávnění správce** pro spuštění; vždy může běžet jen jediná instance
- Vždy vázán na **konkrétní verzi** systému Windows
  - Nelze použít Sysprep z Windows 10 ve Windows 11
  - Umístěn v adresáři `%WINDIR%\System32\Sysprep`
- Počítač nesmí být **členem domény** (Sysprep ho z domény odebere)
- **Grafické rozhraní** od Windows 8.1 zastaralé – doporučuje se příkazová řádka

<!-- Sysprep není v Total Commanderu a jiných 32-bitových správcích souborů na 64-bitovém OS vidět ve <windows>\System32\Sysprep, jelikož nefunguje folder redirection, který automaticky přesměrovává do <windows>\Sysnative\Sysprep.

Příprava instalace systému Windows na doručení uživateli znamená dostat systém Windows do stavu, kdy je dokončena instalace i konfigurace systému Windows a zbývá pouze zadat posledních pár informací, jenž zná pouze uživatel (např. název počítače, názvy uživatelů, jenž budou daný systém používat, atd.). V tomto stavu se často nacházejí notebooky s předinstalovaným systémem.

Od Windows 10 1607 lze Sysprep spustit i na instalaci, která vznikla upgradem (např. Windows 10 22H2 → Windows 11) – hodí se pro průběžnou aktualizaci referenční bitové kopie. Nepodporované je použití Sysprep na již nasazeném produkčním počítači, spuštění pod účtem SYSTEM (Task Scheduler, PsExec) a automatizace přes RunSynchronous.

Pozor: aktualizace aplikací z Microsoft Store před generalize způsobí selhání Sysprep („was installed for a user, but not provisioned for all users“) – aplikace musí být provisionované pro všechny uživatele.

# Přepínače

`Sysprep.exe [/oobe | /audit] [/generalize] [/mode:vm] [/reboot | /shutdown | /quit] [/quiet] [/unattend:<soubor.xml>]`

| Přepínač | Popis |
| --- | --- |
| `/generalize` | Připraví instalaci systému Windows na zachycení |
| `/oobe` | Restartuje počítač do Windows Welcome (OOBE) režimu |
| `/audit` | Restartuje počítač do Audit režimu |
| `/mode:vm` | Zobecnění VHD(X) pro nasazení na stejném hypervizoru (jen zevnitř VM) |
| `/reboot`, `/shutdown`, `/quit` | Restartuje / vypne počítač / jen ukončí Sysprep |
| `/quiet` | Bez potvrzovacích dialogů (automatizace, povinné na Server Core) |
| `/unattend:<soubor.xml>` | Aplikuje nastavení ze zadaného souboru odpovědí; soubor přepíše cache v `%WINDIR%\Panther` a použije se v dalších průchodech |

/mode:vm přeskočí detekci hardwaru – VHD(X) se pak smí nasadit jen na VM se stejným hardwarovým profilem (např. Hyper-V → Hyper-V). Spuštění VM režimu mimo virtuální stroj není podporováno.

# Sysprep /generalize

- **Před ukončením** systému
  - Odstraní všechny unikátní informace v systému
  - Resetuje SID identifikátor počítače
  - Smaže body obnovení systému a protokoly událostí
  - Odinstaluje (ale neodstraní) ovladače zařízení – lze potlačit nastavením `PersistAllDeviceInstalls`
- **Při příštím startu** systému
  - Vytvoří nový SID identifikátor (průchod specialize)
- Limit spuštění na jedné bitové kopii: **1001×** (Windows 8.1+; Windows 7 pouze 3×)
  - Historie: reset aktivační lhůty a nastavení `SkipRearm` – u volume/retail klíčů dnes nepotřebné

<!-- KMS (Key Management Services) klienti jsou klienti, kterým KMS poskytuje volume licence; aktivace probíhá automaticky, takže SkipRearm (reset „rearm“ počítadla aktivační lhůty) už není třeba řešit. Limit 3 spuštění platil pro Windows 7 / Server 2008 R2; od Windows 8.1 / Server 2012 je limit 1001 – po jeho vyčerpání je nutné bitovou kopii vytvořit znovu.

Pokud Sysprep skončí chybou, na stejné instalaci už ho znovu spustit nelze – je třeba bitovou kopii znovu nasadit.

Zdroj: https://learn.microsoft.com/en-us/windows-hardware/manufacture/desktop/sysprep--generalize--a-windows-installation -->

# Audit režim

- Umožňuje **modifikaci systému** před zachycením
  - Instalace ovladačů
  - Instalace aplikací (ne z Microsoft Store)
- Neprovádí se **uživatelská konfigurace** systému po dokončení instalace nebo úpravy systému
  - Přeskočení (ignorování) Windows Welcome
  - Přeskočení přípravy plochy, inicializace profilu apod.
- Přihlášení pod **vestavěným účtem Administrator**; na ploše se zobrazí okno *System Preparation Tool*
- Vhodný pro **ověření instalace** před nasazením na klientské počítače

# Windows Welcome režim

- **Poslední část instalace** systému Windows
  - Přijmutí licenčních podmínek
  - Vytvoření uživatelských účtů
  - Pojmenování počítače, výběr oblasti a jazyka, …
- Často označován jako **Machine OOBE** (*out-of-box experience*)
- Windows 11 Home a Pro (osobní použití) vyžadují při OOBE **internet a účet Microsoft**
  - Firemní zařízení: přihlášení pracovním účtem → Microsoft Entra ID, Intune, **Windows Autopilot**
- Pomocí **CTRL+SHIFT+F3** na úvodní obrazovce lze přepnout do Audit režimu

# Informace o činnosti nástroje Sysprep

- **Protokoly** (*log files*) – podrobné informace o činnosti nástroje Sysprep (včetně chyb)
  - `setupact.log` (průběh), `setuperr.log` (chyby)
- **Uložení protokolů** týkajících se
  - **Zobecňování počítače** (*generalize*)
    - V adresáři `%WINDIR%\System32\Sysprep\Panther`
  - **Specializace počítače** (*specialize*)
    - V adresáři `%WINDIR%\Panther`
  - **Bezobslužné instalace** Windows (OOBE)
    - V adresáři `%WINDIR%\Panther\Unattendgc`
- **Servisní operace DISM**: `%WINDIR%\Logs\DISM\dism.log`, `%WINDIR%\Logs\CBS\CBS.log`

# Konfigurační průchody

- **Fáze instalace** systému Windows (*Windows Setup*) – beze změny i ve Windows 11 24H2/25H2
- V každém průchodu **aplikace nastavení** z určitých sekcí souboru odpovědí (`Unattend.xml`)
  - Řadu nastavení lze aplikovat pouze v určitých fázích
    - Možnost ověření pomocí Windows SIM (součást ADK)
  - Řadu nastavení lze aplikovat v jedné nebo více fázích
- Celkem **7 konfiguračních průchodů**
  - Instalace může procházet jen některými z nich
  - Číslování 1–7 na dalších snímcích odpovídá pořadí ve Windows SIM (generalize před specialize) – stejně jako v E02; chronologii běhu ukazují šipky
  - Většinu nastavení lze umístit do specialize nebo oobeSystem

# Předinstalační prostředí (Windows PE)

- **Windows Preinstallation Environment** – odlehčená verze systému Windows
  - Dostupná ve verzi **amd64** a **arm64** (Windows PE add-on pro ADK)
  - 32-bitová (x86) verze naposledy v add-onu pro Windows 10 2004 – Windows 11 s ní nasadit nelze
- **Možnosti bootování**
  - **USB Flash Disk** nebo **ISO/DVD** (nejčastější), pevný disk (interní, externí nebo virtuální VHDX)
  - **Preboot Execution Environment** (PXE) – síťové bootování
  - Běží celý z paměti (RAM disk), minimum 512 MB RAM
- **Omezení**: po 240 hodinách běhu se restartuje, změny se po restartu ztrácejí, médium FAT32 (soubor max. 4 GB)
- Zahrnuje **nástroje pro obnovu** systému Windows
  - Windows Recovery Environment (Windows RE) je postaveno na Windows PE
- Pro instalaci Windows 11 z WinPE nutné komponenty **WinPE-WMI** a **WinPE-SecureStartup** (kontrola TPM)

# Příprava Windows PE

- **Instalace Windows ADK** + Windows PE add-on stejné verze, spuštění konzole *Deployment and Imaging Tools Environment* jako správce
- **Vytvoření pracovního adresáře** Windows PE
  - `copype <architektura> <adresář>` – např. `copype amd64 D:\winpe`
    - Podpora architektur amd64 a arm64 (x86 jen ve starých add-onech pro Windows 10)
    - Vytvoří `<adresář>\media` (boot.wim v `media\sources`), `mount`, `fwfiles`
- **Úprava** `boot.wim` (nepovinná)
  - `dism /Mount-Image /ImageFile:<adresář>\media\sources\boot.wim /Index:1 /MountDir:<adresář>\mount`
  - Přidání ovladačů (`/Add-Driver`), volitelných komponent (`/Add-Package`), nástrojů, aktualizací (LCU)
  - `dism /Unmount-Image /MountDir:<adresář>\mount /Commit`
- **Vytvoření ISO obrazu / USB disku** s Windows PE
  - `MakeWinPEMedia {/ISO | /UFD} <adresář> {<adresář>\winpe.iso | <jednotka-usb>} [/bootex]`

# Windows Imaging soubory

- Soubory s příponou `.wim` obsahující **jednu nebo více bitových kopií** (kontejner pro bitové kopie)
  - Identifikace pomocí indexu nebo unikátního názvu (`dism /Get-ImageInfo`)
- **Rozdělení do více částí**
  - Soubory s příponou `.swm` (split/spanned .wim) – `dism /Split-Image`, kvůli limitu 4 GB na FAT32
- **Varianta ESD** – `.esd` (*Electronic Software Download*)
  - Stejný formát se silnější kompresí *recovery* (LZMS): `dism /Export-Image … /Compress:recovery`
  - Není šifrovaný – jen komprimovaný; používá ho Windows Update a Media Creation Tool (`install.esd`)
- **Připojení jako adresář** (`dism /Mount-Image`)
  - Vyžaduje ovladač WIM Mount (`wimmount.sys`, součást Windows)
- **Imaging API** (`Wimgapi.dll`) a **DISM API** – rozhraní pro práci s `.wim` soubory z C/C++

# Full Flash Update (FFU)

- **Sector-based** kontejner celého fyzického disku (všechny oddíly včetně EFI, MSR a Recovery)
  - Komprimovaný kontejner (`/Compress:default`, výchozí), katalog a hash tabulka pro ověření integrity při nasazení
  - Rychlejší zachycení i nasazení než WIM (výrobní linka, hromadné přeinstalace), ale větší soubor
- **Zachycení a nasazení** z Windows PE (číslo disku dle `diskpart` → `list disk`)
  - `dism /Capture-Ffu /ImageFile:D:\disk.ffu /CaptureDrive:\\.\PhysicalDrive0 /Name:disk0`
  - `dism /Apply-Ffu /ImageFile:D:\disk.ffu /ApplyDrive:\\.\PhysicalDrive0`
  - `dism /Optimize-Ffu` (Windows 10 1903+) – nasazení i na menší disk, přizpůsobení oddílu Windows
  - `dism /Split-Ffu` do `.sfu` – jen u nekomprimovaného FFU (`/Compress:none`)
- **Omezení**: jen GPT disky, nelze zachytit šifrovaný (BitLocker) disk ani vyloučit soubory, bez optimalizace jen na stejný nebo větší disk
- **Úprava**: `dism /Mount-Image … /Index:1` připojí oddíl Windows jako u VHDX

| | WIM | VHD/VHDX | FFU |
| --- | --- | --- | --- |
| Styl | soubory | sektory | sektory |
| Zachytí | soubory až po celý oddíl | celý disk vč. oddílů | celý disk vč. oddílů |
| Aplikace | přidá soubory na oddíl | přepíše disk | přepíše disk |

# Přidávání a odebírání bitových kopií

- **Přidání bitové kopie** oddílu disku do existujícího `.wim` souboru (stejný typ komprese)
  - `Dism /Append-Image /ImageFile:<cesta-k-wim> /CaptureDir:<jednotka> /Name:<název>`
- **Odebrání bitové kopie** z `.wim` souboru
  - `Dism /Delete-Image /ImageFile:<cesta-k-wim> {/Index:<index> | /Name:<název>}`
- **Export bitové kopie** do nového souboru (optimalizace velikosti, změna komprese, `.esd`)
  - `Dism /Export-Image /SourceImageFile:<wim> /SourceIndex:<i> /DestinationImageFile:<nový> [/Compress:…]`

| Další přepínače | Popis |
| --- | --- |
| `/Verify` | Ověří zachycené soubory (chyby, duplikáty, …) |
| `/CheckIntegrity` | Ověří poškození .wim souboru (pokud je poškozen, přidávání selže) |

<!-- Odebrat bitovou kopii z .wim souboru je možné jen v případě, že .wim soubor obsahuje více než jednu bitovou kopii (pokud obsahuje pouze jednu, lze odebrání realizovat smazáním .wim souboru).

# Pevně daná velikost (fixed)

- **Neměnná velikost** `.vhd`/`.vhdx` souboru
  - Alokace celé velikosti virtuálního disku při vytváření
- **Dobrá propustnost**
- Garantuje **dostupnost veškerého volného místa**
- Doporučeno pro **produkční servery** a data zákazníků

---

# Dynamicky se zvětšující (dynamic)

- **Velikost souboru** `.vhd`/`.vhdx` je dána velikostí dat zapsaných (uložených) v tomto souboru
  - Postupná alokace při zapisování na virtuální disk do dosažení maximální velikosti virtuálního disku
- Často označován **Expandable** (diskpart) nebo **Dynamic** (PowerShell, výchozí u `New-VHD`)
- Může dojít k **selhání**, pokud není na fyzickém disku dostatek místa pro dodatečné alokace
- Doporučeno pro **vývoj a testování** (u VHD hrozilo poškození při výpadku napájení)

---

# Rozdílový (differencing)

- **Dynamicky se zvětšující**
- **Synovský** (*child*) virtuální disk
  - Obsahuje pouze změny oproti otcovskému disku
- **Otcovský** (*parent*) virtuální disk
  - Pouze pro čtení (nesmí být modifikován)
  - Může být fixed, dynamic nebo differencing
- **Slučování** synovských a otcovských virtuálních disků
  - Pomocí nástroje diskpart (`merge vdisk`)
  - Pomocí PowerShell příkazu `Merge-VHD`
- **Typické použití**: laboratorní VM nad společným rodičem (AutomatedLab: `BASE_*.vhdx` na `E:`)

# Bootování z virtuálního disku

- **Nativní VHD bootování** (*Native VHD Boot*) – Windows běží z `.vhdx` bez hypervizoru
  - Windows 10/11 a Windows Server: vyžaduje formát VHDX (`.vhd` už nelze)
  - Historie: Windows 7 jen Enterprise/Ultimate, Windows 8/10 Pro a Enterprise
- **Požadavky**: systémový oddíl se zavaděčem (BCD) + oddíl s `.vhdx`; dostatek místa pro rozbalení dynamického disku a stránkovací soubor (je mimo VHDX)
- **Omezení**
  - Nelze používat BitLocker (ani na hostitelském svazku s VHDX, ani uvnitř)
  - Nelze používat hibernaci (režim spánku ano)
  - VHDX nelze vnořit do jiného VHDX, nelze bootovat ze sdílené složky SMB ani z dynamického disku
  - Soubor nesmí mít „mark of the web“ (`Zone.Identifier`) – od aktualizací z listopadu 2022 boot selže
  - Rozdílové disky jen pro vývoj a testování (doporučení Microsoftu), ne pro produkci

# Konfigurace zavaděče (bootloader)

- **Doporučený postup** (z Windows PE nebo běžících Windows): připojit VHDX a nechat `bcdboot` vytvořit záznam
  - `diskpart` → `select vdisk file=M:\win11.vhdx` → `attach vdisk` (VHDX dostane písmeno, např. `V:`)
  - `dism /Apply-Image /ImageFile:install.wim /Index:1 /ApplyDir:V:\` (jen u prázdného disku)
  - `bcdboot V:\Windows /s S: /f UEFI` (`S:` = systémový oddíl EFI)
- **Ruční postup** pomocí `bcdedit`
  - `bcdedit /copy {current} /d "<název>"` – vrací GUID nové položky
  - `bcdedit /set <guid> device vhd=[locate]\win11.vhdx`
  - `bcdedit /set <guid> osdevice vhd=[locate]\win11.vhdx`
  - `bcdedit /set <guid> detecthal on`

Při více záznamech se zobrazí nabídka zavaděče; výchozí položku a timeout nastavíte bcdedit /default <guid> a /timeout.

# Virtuální disky a Hyper-V generace 2

- Generace VM se volí při vytvoření a nelze ji změnit; **generace 2** je doporučená
  - Firmware **UEFI** se Secure Boot (výchozí zapnuto), virtuální TPM – nutné pro Windows 11 jako hosta (gen. 1 Windows 11 nepodporuje)
  - Boot jen ze **SCSI** řadiče – `.vhdx` (až 64 TB, online změna velikosti) nebo `.iso`; žádné IDE, floppy ani starší (legacy) síťový adaptér
  - **PXE boot** přes syntetický síťový adaptér (IPv4 i IPv6, `Set-VMFirmware -IPProtocolPreference`)
- **Generace 1**: BIOS, IDE boot z `.vhd`/`.vhdx` (max. 2 TB), legacy NIC pro PXE – jen pro starší hosty
- Jeden VHDX nemá být bootovatelný pro **obě generace**; rozložení GPT/UEFI z gen. 2 odpovídá nativnímu VHD bootu na UEFI počítači
- V laboratoři: **AutomatedLab** vytváří VM Windows 11 Pro jako generaci 2 nad rozdílovými disky `BASE_*.vhdx`
