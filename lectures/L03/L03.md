# Nástroje pro správu bitových kopií

- DISM (Deployment Image Servicing and Management)
  - Nástroj pro správu (vytváření, úpravu a nasazování) bitových kopií systému (Windows images)
    - Úprava Windows PE bitových kopií
    - Povolení / zakázání funkcí systému Windows, funkce na vyžádání (FoD)
    - Přidání / odebrání / vypsání balíků, ovladačů a aplikací (MSIX)
    - Konfigurace oblastních a jazykových nastavení
    - Upgrade edice systému Windows
  - Součást systému Windows (`dism.exe`, PowerShell modul `Dism`) i Windows ADK (Deployment Tools)
    - Verze DISM musí být alespoň tak nová jako spravovaná bitová kopie
    - Hostitel x64 může spravovat i bitové kopie x86 (Windows 10); Windows 11 existuje jen jako x64 a ARM64

# Správa bitových kopií

- Online (online servicing, dism přepínač `/Online`)
  - Správa nasazené bitové kopie (tzn. běžícího systému)
- Offline (offline servicing, dism přepínač `/Image`)
  - Správa bitové kopie ve .wim/.vhd/.vhdx souborech (od Windows 10 1709 i .ffu)
  - Umožňuje úpravu bitové kopie bez nutnosti jejího nasazení a opětovného zachycení (uložení)
    - Vyšší bezpečnost
      - Aplikace aktualizací před prvním startem systému
    - Není potřeba resetovat dobu aktivace Windows
    - Možnost výměny souborů odpovědí

<!--

# Základní informace o bitových kopiích

- Informace o bitových kopiích uložených ve .wim, .vhd/.vhdx nebo .ffu souboru
  - `dism /Get-ImageInfo /ImageFile:<cesta-k-wim/vhd/ffu> [/Index:<index> | /Name:<název>]`
  - U .vhd/.vhdx/.ffu souborů se musí vždy použít `/Index:1`, jelikož mohou obsahovat pouze jednu bitovou kopii
  - PowerShell: `Get-WindowsImage -ImagePath <cesta>`
- Informace o všech připojených bitových kopiích
  - `dism /Get-MountedImageInfo`

# Připojení bitové kopie

- Připojení bitové kopie do zadaného adresáře
  - `dism /Mount-Image /ImageFile:<cesta-k-wim/vhd/ffu> {/Index:<index> | /Name:<název>} /MountDir:<adresář>`
    - Adresář musí existovat, být prázdný a nesmí být symbolický odkaz
  - PowerShell: `Mount-WindowsImage -ImagePath <cesta> -Index <n> -Path <adresář>`

| Další přepínače | Popis |
| --- | --- |
| `/ReadOnly` | Připojí bitovou kopii pouze pro čtení (vyžadováno u bitových kopií ve .wim/.vhd/.vhdx souborech uložených například na DVD nebo jiném médiu jen pro čtení) |
| `/Optimize` | Urychlí připojení bitové kopie (úkony prováděné při připojení budou provedeny při prvním přístupu k obsahu souboru) |
| `/CheckIntegrity` | Ověří poškození .wim souboru (pokud je poškozen, připojení selže a bitová kopie nebude připojena), nelze použít u .vhd/.vhdx souborů |

<!--
Připojovaný .wim/.vhd/.vhdx soubor nesmí být uložen na oddílu disku se souborovým systémem FAT32. Neplatí pokud je připojován pouze pro čtení a jeho velikost tímto nemůže překročit 4GB (limit pro soubory u FAT32). ReFS jako umístění bitové kopie DISM nepodporuje.

Při připojování bitové kopie se nekopírují její data do cílového adresáře, jen se vytvoří adresářová struktura se zástupnými soubory (na způsob sparse files). Fyzicky se data nakopírují teprve tehdy, když se s nimi začne něco dělat (zobrazení, modifikace, …).

# Uložení bitové kopie

- Zapsání změn provedených v připojené bitové kopii zpět do jejího .wim/.vhd/.vhdx souboru
  - `dism /Commit-Image /MountDir:<adresář>`
  - PowerShell: `Save-WindowsImage -Path <adresář>`
  - Časově náročná operace
    - Není vhodné zapisovat změny při každé modifikaci bitové kopie, lepší je zapsat je až před odpojením bitové kopie

| `/Append` | Přidá bitovou kopii do existujícího .wim souboru jako novou (namísto přepsání původní bitové kopie), nelze použít u .vhd/.vhdx souborů |

# Odpojení bitové kopie

- Odpojení bitové kopie ze zadaného adresáře
  - `dism /Unmount-Image /MountDir:<adresář> {/Commit | /Discard}`
    - Přepínač `/Commit` vynutí uložení změn v bitové kopii před jejím odpojením (přepínač `/Discard` je zahodí)
  - PowerShell: `Dismount-WindowsImage -Path <adresář> {-Save | -Discard}`

| Další přepínače | Popis |
| --- | --- |
| `/CheckIntegrity` | Ověří poškození .wim souboru (v případě poškození ho zkusí opravit a když neuspěje, odpojení selže), nelze použít u .vhd/.vhdx/.ffu souborů |
| `/Append` | Přidá bitovou kopii do existujícího .wim souboru jako novou (namísto přepsání původní bitové kopie), nelze použít u .vhd/.vhdx/.ffu souborů |

# Údržba připojených bitových kopií

- Obnova připojení bitové kopie v daném adresáři
  - `dism /Remount-Image /MountDir:<adresář>`
- Odstranění prostředků poškozených připojení
  - `dism /Cleanup-Mountpoints`
  - PowerShell: `Clear-WindowsCorruptMountPoint`
  - Provádí se u všech připojených bitových kopií
  - Neodpojí ani nesmaže připojené bitové kopie, které lze obnovit pomocí `/Remount-Image`

# Správa edicí operačního systému

- Změna edice systému Windows v bitové kopii (pouze na vyšší edici stejné rodiny)
  - `dism /Image:<adresář> /Set-Edition:<id-edice>`
  - Bitová kopie musí obsahovat soubory dané edice (např. install.wim z média obsahuje Home, Pro, Education, …)
  - Změna (zadání) licenčního klíče (po změně edice)
    - `dism /Image:<adresář> /Set-ProductKey:<licenční-klíč>`
    - Během instalace (přes soubor odpovědí nebo v OOBE)
- Změna edice běžícího systému Windows
  - `dism /Online /Set-Edition:<id-edice> /AcceptEula /ProductKey:<licenční-klíč>`
  - Podporováno pouze u Windows Server
  - Klient (Windows 11): zadání klíče vyšší edice – **Nastavení > Systém > Aktivace**, `changepk.exe /ProductKey <klíč>` nebo `slmgr /ipk <klíč>`

# Jazykové balíčky a jazykové funkce ve Windows 11

- Zdroj: **Languages and Optional Features ISO** (VLSC / Visual Studio subscriptions), případně Windows Update (online)
- Jazykový balíček (.cab) se přidává jako balík
  - `dism /Image:<adresář> /Add-Package /PackagePath:<ISO>\LanguagesAndOptionalFeatures\Microsoft-Windows-Client-Language-Pack_x64_cs-cz.cab`
- Jazykové funkce na vyžádání (Basic, Fonts, Handwriting, OCR, Speech, TextToSpeech) přes `/Add-Capability`
  - `dism /Image:<adresář> /Add-Capability /CapabilityName:Language.Basic~~~cs-CZ~0.0.1.0 /CapabilityName:Language.OCR~~~cs-CZ~0.0.1.0 /Source:<ISO> /LimitAccess`
- Pořadí: **jazyky a FoD → aktualizace (LCU) → aplikace**; po přidání jazyka je nutné LCU přidat znovu
- Ověření: `/Get-Packages /Format:Table`, `/Get-Capabilities /Format:Table | findstr /i installed`
- Běžící systém: Nastavení > Čas a jazyk > Jazyk a oblast nebo `Install-Language cs-CZ` (modul LanguagePackManagement)

# Správa ovladačů

- Jsou podporovány jen ovladače ve formátu .inf (balíček ovladače: .inf, .sys, .cat, …)
  - Nelze použít ovladače uložené v .msi balících nebo jiných instalačních balících (např. v .exe souborech)
- Offline (připojená bitová kopie): **DISM** – `/Add-Driver`, `/Remove-Driver`, `/Get-Drivers`, `/Export-Driver`

# Správa balíků operačního systému

- Jsou podporovány balíky ve formě .cab a .msu souborů (garantují bezobslužnou instalaci)

# Kumulativní aktualizace v bitové kopii

- Měsíční aktualizace zabezpečení (2. úterý, „LCU“) je kumulativní a obsahuje i aktualizaci servisního zásobníku (SSU)
  - Windows 11 25H2 je enablement package nad platformou 24H2 – obě verze sdílejí stejné LCU
- **Checkpoint cumulative updates** (od Windows 11 24H2)
  - LCU může vyžadovat předchozí „checkpoint“ LCU; další LCU obsahují jen binární rozdíly oproti checkpointu → menší balíky
  - Windows Update a WSUS to řeší samy; při ruční instalaci .msu (katalog Microsoft Update) je nutné mít checkpointy
  - DISM: `/Add-Package /PackagePath:<složka-s-cílovou-LCU>` – ve složce jen cílová LCU a její checkpointy, DISM je najde a nainstaluje v pořadí
- Ověření: `dism /Image:<adresář> /Get-Packages /Format:Table` → `Package_for_RollupFix~31bf3856ad364e35~amd64~~<build>.<revize>…`, `State : Installed`
- Po aktualizaci offline bitové kopie: aktualizovat i `winre.wim`, po aplikaci na disk znovu `bcdboot`
- Zmenšení: `dism /Image:<adresář> /Cleanup-Image /StartComponentCleanup [/ResetBase]` (po `/ResetBase` nelze aktualizace odinstalovat)

# Průběh instalace balíků

- Přidané balíky jsou v offline bitové kopii ve stavu „čeká na instalaci“ (install pending) a nainstalují se až při spuštění systému obsaženého v dané bitové kopii
- Dokud čekající akce neproběhnou, nelze zpracovat další (proto `/PreventPending`)
- Pokud je instalace balíku závislá na přítomnosti jiných balíků, je lepší pro instalaci použít soubor odpovědí, kde lze definovat pořadí instalace
- Balíky jsou instalovány v pořadí v jakém jsou zadány na příkazové řádce

# Stavy ovladačů a balíků

| Stav | Událost / akce | Následek | Nový stav |

| Nepřítomen (*not present*) | **Přidání** (akce) | Vložení souborů | Čeká na instalaci (*install pending*) |

# Správa aplikací MSIX (Microsoft Store)

- Balíčky .msix / .msixbundle (dříve .appx / .appxbundle; přepínače DISM stále nesou název *Appx*)
  - Zřízená (*provisioned*) aplikace je součástí bitové kopie a nainstaluje se každému novému uživateli při prvním přihlášení
  - Spravovat lze offline i online; seznam: `dism /Online /Get-ProvisionedAppxPackages`
- Přidání (zřízení) aplikace
  - `dism /Image:<adresář> /Add-ProvisionedAppxPackage /PackagePath:<app.msixbundle> [/DependencyPackagePath:<framework.msix>] {/LicensePath:<licence.xml> | /SkipLicense} [/Region:all]`
  - PowerShell: `Add-AppxProvisionedPackage -Online -PackagePath <cesta> -SkipLicense`
- Odebrání zřízení aplikace
  - `dism /Online /Remove-ProvisionedAppxPackage /PackageName:<název-balíčku>`
  - Uživatelům, kteří už aplikaci mají, zůstane – per-user odinstalace `Remove-AppxPackage` (modul Appx: `Get-AppxPackage`, `Add-AppxPackage`)
- Sideloading (instalace mimo Microsoft Store): balíček podepsaný certifikátem, kterému zařízení důvěřuje; zásada „Allow all trusted apps to install“ / Intune; Nastavení > Systém > Pro vývojáře > Režim pro vývojáře

# Oprava a úklid úložiště komponent

- Úložiště komponent (`C:\Windows\WinSxS`) – zdroj pro opravy systémových souborů a obnovu funkcí
- Oprava běžícího systému (postupně)
  - `dism /Online /Cleanup-Image /CheckHealth` – jen zjistí, zda je bitová kopie označena jako poškozená
  - `dism /Online /Cleanup-Image /ScanHealth` – prohledá úložiště komponent (minuty)
  - `dism /Online /Cleanup-Image /RestoreHealth [/Source:<mount>\Windows /LimitAccess]` – opraví z Windows Update nebo ze zadaného zdroje
  - poté `sfc /scannow` (System File Checker) – opraví chráněné systémové soubory z opraveného úložiště
  - PowerShell: `Repair-WindowsImage -Online -RestoreHealth`
- Úklid
  - `dism /Online /Cleanup-Image /AnalyzeComponentStore` – skutečná velikost WinSxS a doporučení
  - `dism /Online /Cleanup-Image /StartComponentCleanup [/ResetBase]` – odstraní nahrazené komponenty
- Offline záchrana: `dism /Image:<adresář> /Cleanup-Image /RevertPendingActions` (jen u nespustitelného systému)

# Nástroje pro nasazování Windows (2026)

- **Windows ADK** – Windows PE, DISM, USMT, Windows System Image Manager, Windows Configuration Designer
  - Základní stavební kameny; ruční nebo skriptované nasazení (WinPE + `dism /Apply-Image`, FFU)
- **Windows Autopilot + Microsoft Intune** – cloudové zřizování bez vlastní bitové kopie
  - Zařízení s OEM instalací Windows se při OOBE připojí k Entra ID, zaregistruje do Intune a nakonfiguruje (zásady, aplikace)
- **Microsoft Configuration Manager** (dříve SCCM / MECM) – nasazení bitových kopií on-premises
  - Sekvence úloh (task sequences), PXE, distribuční body, správa ovladačů, aktualizací a aplikací
- **Zřizovací balíčky (.ppkg)** – Windows Configuration Designer; konfigurace bez bitové kopie pro menší nasazení
- **Windows 365 / Azure Virtual Desktop** – Cloud PC; bitová kopie se stává šablonou VM v Azure
- Historie: **MDT** (Microsoft Deployment Toolkit) – ukončen, poslední build 8456; **WDS** – deprecated, nasazení boot.wim z média Windows 11 je blokováno

# Tlustá bitová kopie (thick image)

- Kromě operačního systému obsahuje základní aplikace, jazykové balíky a další soubory
- Jednoduché vytváření
  - Vyžaduje minimum skriptování (většinou žádné)
- Rychlé nasazení
- Pracná aktualizace (po každém měsíčním LCU a změně aplikací znovu zachytit)
- Vytvoření: referenční virtuální počítač (Hyper-V) v audit módu → `sysprep /generalize` → zachycení (`dism /Capture-Image`, FFU), nebo sekvence úloh *build and capture* v Configuration Manageru
- Často se používá jako forma zálohy nebo šablony
  - Bootovatelné virtuální disky (VHDX), šablony VM pro Windows 365 / AVD

<!--
Historie: pro vytvoření tlusté bitové kopie se dříve používal MDT (sekvence Sysprep and Capture); dnes je tuto roli v on-premises prostředí přebírá Configuration Manager, v laboratoři ruční postup z L02 (audit mód, sysprep, WinPE, DISM).
-->

---

# Tenká bitová kopie (thin image)

- Obsahuje pouze operační systém (případně jen pár základních aplikací nebo jazykových balíků)
- Složitější vytváření
  - Aplikace a jazykové balíky instalovány až dodatečně
    - Potřeba mít infrastrukturu pro distribuci aplikací (Intune, Configuration Manager, winget)
    - Často vyžaduje velké množství skriptování
- Nemusí se aktualizovat
- Nižší bezpečnost
  - Aktualizace aplikovány až po nasazení (za běhu)
- Dnešní standard: OEM bitová kopie z výroby + Windows Autopilot + Intune (žádná vlastní bitová kopie)

<!--
Windows Autopilot „transformuje“ OEM instalaci do firemního stavu (zásady, aplikace, změna edice Pro → Enterprise) – správce neudržuje žádnou vlastní bitovou kopii ani ovladače pro jednotlivé modely.

Zdroj: https://learn.microsoft.com/en-us/autopilot/overview
-->

---

# Hybridní bitová kopie (hybrid image)

- Kombinace tlusté a tenké bitové kopie
  - Automatická instalace aplikací a jazykových balíků při prvním startu systému (instalace ze síťového zdroje)
  - Výhody tenké bitové kopie, ale jednodušší vytváření
- Vyšší bezpečnost
  - Instalace před prvním přihlášením uživatele
- Není nutná infrastruktura pro distribuci aplikací
- Delší čas instalace
- Někdy jako tlustá bitová kopie rozšiřující tenkou

<!--

Typ 2: vytvoření několika tlustých bitových kopií s různými aplikacemi, ovladači apod. z jedné základní tenké bitové kopie (inkrementální vytváření bitových kopií).

# Aplikace bitové kopie (WIM)

- Aplikace (rozbalení) bitové kopie uložené ve .wim (.swm, .esd) souboru na vybraný oddíl disku
  - `dism /Apply-Image /ImageFile:<cesta-k-wim> {/Index:<index> | /Name:<název>} /ApplyDir:<jednotka>`
  - PowerShell: `Expand-WindowsImage -ImagePath <cesta> -Index <n> -ApplyPath C:\`
  - Bitové kopie ve .vhd/.vhdx souborech nelze aplikovat (rozbalit); lze ale aplikovat .wim do připojeného a naformátovaného VHDX
- Typický postup ve WinPE (UEFI/GPT): `diskpart` (oddíly EFI, MSR, Windows, Recovery) → `dism /Apply-Image … /ApplyDir:W:\` → `bcdboot W:\Windows /s S:` → po aktualizacích znovu `bcdboot`

| Další přepínače | Popis |
| --- | --- |
| `/SWMFile:<vzor>` | Aplikace rozdělené bitové kopie (`install*.swm`, např. kvůli limitu 4 GB na FAT32 médiu) |
| `/Compact` | Kompaktní režim (komprimované soubory OS na disku, šetří místo; nahrazuje WIMBoot) |
| `/EA` | Aplikuje rozšířené atributy (od Windows 10 1607) |
| `/Verify` | Ověří zachycené soubory (chyby, duplikáty, …) |
| `/CheckIntegrity` | Ověří poškození .wim souboru (pokud je poškozen, aplikace selže) |

<!--

# Bitové kopie FFU (Full Flash Update)

- Sektorová bitová kopie celého fyzického disku (všechny oddíly – EFI, MSR, Windows, Recovery) vs. souborový formát WIM
  - Rychlejší nasazení, větší soubor, nelze vyloučit soubory; jen GPT disky, ne šifrované (BitLocker) a ne s aktivním VSS
  - Určeno hlavně pro výrobu / servis (factory floor), od Windows 10 1709 (WinPE 1709+)
- Zachycení (z WinPE, referenční PC po `sysprep /generalize`)
  - `dism /Capture-FFU /ImageFile:D:\WinOEM.ffu /CaptureDrive:\\.\PhysicalDrive0 /Name:disk0 [/Compress:none]`
- Optimalizace pro jinak velké disky (od Windows 10 1903): `dism /Optimize-FFU /ImageFile:D:\WinOEM.ffu [/PartitionNumber:<n>]`
  - Neoptimalizované FFU lze aplikovat jen na stejně velký nebo větší disk
- Aplikace: `dism /Apply-FFU /ImageFile:N:\WinOEM.ffu /ApplyDrive:\\.\PhysicalDrive0` (žádný diskpart ani bcdboot)
- Servis: `dism /Mount-Image /ImageFile:D:\WinOEM.ffu /Index:1 /MountDir:<adresář>` – připojí se jen oddíl s Windows; informace `dism /Get-ImageInfo`
- Rozdělení: `/Split-FFU` (jen nekomprimované FFU, `/SFUFile`)

<!--

FFU vs. WIM vs. VHDX srovnává článek „WIM vs. VHD vs. FFU: comparing image file formats“ – FFU je vhodné tam, kde se stejná bitová kopie nahrává na mnoho stejných strojů (výroba, učebny se stejným hardwarem), WIM tam, kde se bitová kopie servisuje a nasazuje na různé disky/oddíly.

# Windows Autopilot

- Sada cloudových služeb pro zřízení nových (i resetovaných) zařízení bez vlastní bitové kopie
  - OEM/prodejce (nebo správce) zaregistruje hardwarový hash zařízení do tenantu; při OOBE se zařízení pozná a řídí se **Autopilot profilem**
  - Připojení k **Microsoft Entra ID** (doporučeno; hybridní připojení k AD DS se pro nová zařízení nedoporučuje), automatický zápis do **Intune** (vyžaduje Entra ID P1/P2), přiřazení do skupin, vlastní OOBE, stránka stavu registrace (ESP)
  - Následně zásady, aplikace, změna edice (Pro → Enterprise), Windows Update – vše z Intune

| Scénář | Pro | Interakce | Poznámka |
| --- | --- | --- | --- |
| **User-driven** | zařízení jednoho uživatele | uživatel se přihlásí | funguje i ve VM (bez ověření TPM) |
| **Pre-provisioned** (dříve *white glove*) | zařízení jednoho uživatele | technik (technician flow) + uživatel | vyžaduje TPM attestation – jen fyzický HW |
| **Self-deploying** | kiosky, sdílená zařízení | žádná | jen Entra join, ověření TPM |
| **Existing devices** | přeinstalace stávajících PC | sekvence úloh Configuration Manageru + JSON profil | poté proběhne user-driven Autopilot |
| **Autopilot Reset** | opětovné použití zařízení | lokální / vzdálený reset | zařízení zůstává registrované |

# Microsoft Configuration Manager – nasazení OS

# Zřizovací balíčky (provisioning packages)

- Soubor **.ppkg** = kontejner konfiguračních nastavení aplikovaný na existující instalaci Windows (bez bitové kopie)
  - Nástroj **Windows Configuration Designer** (WCD) – aplikace z Microsoft Store nebo součást Windows ADK
  - Průvodci: desktop, kiosk, HoloLens, Surface Hub; pokročilý editor (Windows Provisioning settings)
- Co lze nastavit: název počítače, kód Product Key (změna edice), odstranění předinstalovaného softwaru, Wi-Fi, připojení k AD DS nebo Entra ID (bulk token), místní správce, aplikace (Win32 i MSIX), certifikáty, zásady (heslo, šifrování, aktualizace), rozložení nabídky Start, VPN/proxy, tapety
- Aplikace balíčku
  - Během OOBE (USB disk – Windows nabídne balíček samo, nebo 5× klávesa Windows), NFC, e-mail, sdílená složka
  - Nastavení > Účty > Přístup do práce nebo do školy > přidat/odebrat zřizovací balíček (*Add or remove a provisioning package*)
  - PowerShell `Add-ProvisioningPackage`, DISM offline i online: `dism /Image:<adresář> /Add-ProvisioningPackage /PackagePath:C:\firma.ppkg`
- Určeno pro desítky až stovky počítačů (SMB, školy – aplikace **Set up School PCs**); pro automatický zápis do Intune se nepoužívá (Autopilot)

# Historie: Microsoft Deployment Toolkit (MDT)

- Bezplatná sada nástrojů Microsoftu (2008–2019) nad Windows ADK/WAIK pro automatizaci nasazení Windows
  - **Deployment Workbench** (MMC) – distribuční sdílení (*deployment share*) s adresáři Operating Systems, Out-of-Box Drivers, Packages, Applications, Task Sequences, Boot (LiteTouchPE), Scripts, USMT; body nasazení (Deployment Share, Linked, Media); výběrové profily
  - **Sekvence úloh** ze šablon (Standard Client Task Sequence, Sysprep and Capture, Standard Client Upgrade, Deploy to VHD, …), řízené `CustomSettings.ini` / `Bootstrap.ini` a MDT databází; skripty VBScript (`ZTIGather`, `LiteTouch.wsf`)
  - **LTI** (samostatně – sdílení, média, WDS), **ZTI** a **UDI** (integrace do SCCM – Configure ConfigMgr Integration, MDT šablony sekvencí)
- Poslední verze **MDT build 8456** (leden 2019): Windows 10 1809, Windows Server 2019, ADK pro Windows 10 1809, Configuration Manager 1810
  - Windows 11, ARM64 ani ADK pro Windows 11 nikdy nebyly podporovány (od ADK 22H2 chybí x86 WinPE → průvodce boot bitové kopie selhává)
- **Ukončení**: oznámeno v prosinci 2024, konec podpory s první verzí Configuration Manageru po 10. 10. 2025 (souvisí s ukončením VBScript)
  - Doporučení: odebrat MDT kroky ze sekvencí úloh a MDT integraci; přejít na **Windows Autopilot** (cloud) nebo **Configuration Manager OSD** (on-premises)
