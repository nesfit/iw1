# Internet Protocol verze 4 (IPv4)

- Protokol **internetové (resp. síťové) vrstvy**, L3
- Zajišťuje **směrování IPv4 datagramů** (paketů)
  - Přenos dat z jednoho síťového rozhraní na druhé
- **Dvě IPv4 adresy** v každém IPv4 datagramu
  - IPv4 adresu **zdroje** (rozhraní, jenž datagram odeslalo)
  - IPv4 adresu **cíle** (rozhraní, kterému se má doručit)
- **IPv4 adresa**
  - Jednoznačná identifikace síťového rozhraní (zařízení) v rámci dané (pod)sítě

<!--

# Formát IPv4 adres

- Délka **32 bitů**
- Zápis v tzv. **tečkové notaci** (v dekadickém tvaru)
  - X.X.X.X kde X je číslo od 0 do 255 (8 bitů, tzv. oktet)
- Skládá se z **adresy (pod)sítě** a **adresy rozhraní**
  - Určeny maskou podsítě

![center w:760](img/s06-obr-zek-13.png)

# Maska podsítě (Subnet Mask)

- Délka **32 bitů**
- **Stejný zápis** jako u IPv4 adres
- **Jedničkové bity** určují, které bity IPv4 adresy jsou bity adresy (pod)sítě
- **Nulové bity** určují, které bity IPv4 adresy jsou bity adresy rozhraní

# Výchozí brána (Default Gateway)

- IP adresa síťového rozhraní **směrovače** (*router*)
- Všechny datagramy směřující do **jiné (pod)sítě** jsou zasílány na adresu výchozí brány

---

# Classless Inter-Domain Routing (CIDR)

- IPv4 adresy dříve děleny do **5 tříd** (třídy A – E)
  - Každá třída měla určenou masku podsítě
- **CIDR** umožňuje explicitně specifikovat masku podsítě pro každou IPv4 adresu
  - Maska podsítě jako počet jedničkových bitů
  - Zápis ve formátu X.X.X.X/Y kde Y je číslo od 0 do 32
- Nutnost uchovávat **informace o masce podsítě**
  - Potřeba pro směrování datagramů
    - Každá IPv4 adresa náleží do sítě identifikované adresou (pod)sítě (adresa rozhraní obsahuje samé nuly)

# Typy IPv4 adres

- **Individuální** (*unicast*)
  - Identifikují právě jedno síťové rozhraní (zařízení)
  - Data se doručují tomuto rozhraní
- **Všesměrové** (*broadcast*)
  - Data se doručují všem síťovým rozhraním (zařízením)
  - Adresa rozhraní obsahuje samé jedničky
- **Skupinové** (*multicast*)
  - Identifikují celou skupinu síťových rozhraní (zařízení)
  - Data se doručují všem členům skupiny

# Speciální IPv4 adresy

- **Neplatná** IPv4 adresa
  - 0.0.0.0
- **Loopback** IPv4 adresa
  - 127.0.0.1 (DNS název localhost)
- **Privátní** IPv4 adresy
  - Adresy náležící do rozsahů privátních sítí
  - Nesměrovatelné v síti internet

# APIPA

- **Automatic Private IP Addressing**
- **Automatické přiřazení** IPv4 adresy v případě, že ji nebylo možné získat od DHCP serveru
  - Generují se IPv4 adresy ze sítě 169.254.0.0/16
  - Výchozí brána se nenastavuje (nesměrovatelné)
  - Lze přiřadit i vlastní (statickou) IPv4 adresu
    - Záložní konfigurace (*Alternativní konfigurace*) v klasickém dialogu TCP/IPv4
- **Ověření konfliktů** IPv4 adres na dané síti
  - Po 10 konfliktech se nastaví neplatná adresa 0.0.0.0

# Směrování

- Provádí se pomocí tzv. **směrovacích tabulek**
  - Informace o dosažitelných (pod)sítích
- **Obecný algoritmus** směrování
  - Pokud je cíl **totožný se zdrojem**
    - Neposílej data na síť (doručení probíhá interně)
  - Pokud je cíl na **stejné (pod)síti**
    - Pošli data na síť (doručení na MAC adresu cíle)

    - Pošli data na výchozí bránu, jenž umožňuje doručení do cílové sítě (doručení na MAC adresu výchozí brány)

# Network Address Translation (NAT)

- Metoda **překladu IP adres** (a portů) z jedné sítě do jiné sítě (např. z privátní sítě do sítě internet)
  - Dochází k úpravě hlaviček IP datagramů (zpomalení)
  - Překlad se provádí na základě překladových tabulek
- **Přístup do sítě internet** pro zařízení s IP adresami, jenž v ní nejsou směrovatelné
  - Překlad privátních IP adres na veřejné IP adresy
  - Počítače na privátní síti nejsou adresovatelné ze sítě internet (nelze se na ně připojit z internetu)
    - Vyšší bezpečnost, problematické poskytování služeb

# Protokol DHCP

- **Dynamic Host Configuration Protocol**
- **Automatická konfigurace** IP adres zařízení
  - Omezená doba platnosti (*lease time*)
  - Možnost rezervace IP adres pro konkrétní zařízení
  - Lze nastavovat i další informace (*options*):
    - výchozí brána, DNS servery, doménová přípona, NTP, PXE boot (option 60/66/67)
- **Obnova** při startu zařízení nebo manuálně
  - Uvolnění IP adresy příkazem `ipconfig /release`
  - Obnova IP adresy příkazem `ipconfig /renew`
  - PowerShell: `Get-NetIPAddress -PrefixOrigin Dhcp`, `Set-NetIPInterface -Dhcp Enabled`

<!--

PXE boot: klient dostane přes DHCP options 66 (Boot Server Host Name) a 67 (Bootfile Name) adresu TFTP serveru a jméno zavaděče; option 60 (PXEClient) se používá, když DHCP a PXE server běží na jednom stroji. # Systém DNS

- **Domain Name System**
- Systém pro **překlad doménových jmen** (*domain name*) na odpovídající IP adresy
- **Kešování** výsledků překladů po dobu TTL
  - Zobrazení aktuální keš příkazem `ipconfig /displaydns` nebo `Get-DnsClientCache`
  - Podpora negativního kešování (*negative caching*)
    - Cíl neexistuje
  - Vyrovnávací paměť (*cache*) lze vymazat i manuálně příkazem `ipconfig /flushdns` nebo `Clear-DnsClientCache`
- **Automatická registrace** zařízení v systému DNS
  - Lze spustit manuálně příkazem `ipconfig /registerdns` nebo `Register-DnsClient`
- **Dotazy**: `nslookup`, `Resolve-DnsName` (viz nástroje)

# Internet Protocol verze 6 (IPv6)

# Formát IPv6 adres

- Délka **128 bitů**
- Zápis v tzv. **dvojtečkové notaci**
  - X:X:X:X:X:X:X:X kde X je hexadecimální číslo od 0000 do FFFF (16 bitů, tzv. skupina / blok)
- Skládá se z **identifikátorů (pod)sítě a rozhraní**
  - Určeny IPv6 prefixem

![center w:850](img/s36-obr-zek-14.png)

<!--

-->

# Zkrácený formát IPv6 adres

- **Vynechání úvodních nul** každé skupiny
  - V každé skupině musí zůstat alespoň jedna číslice
- **Sloučení** po sobě jdoucích nulových skupin
  - Lze provést pouze jednou v rámci dané IPv6 adresy
- **Doporučený tvar** (RFC 5952): malá písmena, co nejdelší běh nul nahradit `::`

<div style="text-align: center; margin-top: 0.8em;">

`2001:0db8:0000:000a:f563:5add:6fc4:152e` → `2001:db8:0:a:f563:5add:6fc4:152e`

`2001:db8:0:a:f563:5add:6fc4:152e` → `2001:db8::a:f563:5add:6fc4:152e`

</div>

<!--
Prefix 2001:db8::/32 je vyhrazen pro dokumentaci a příklady (RFC 3849) – původní příklady s fec0:: používaly site-local adresy, které jsou od RFC 3879 (2004) zrušené.
-->

# IPv6 prefix

- Určuje kolik **počátečních bitů** IPv6 adresy naleží identifikátoru (pod)sítě (vychází z CIDR notace)
- **Stejný zápis** jako u masky podsítě u CIDR
  - X:X:X:X:X:X:X:X/Y kde Y je číslo od 0 do 128
- **Příklad** IPv6 adresy s definovaným prefixem
  - `2001:0db8:0000:000a:f563:5add:6fc4:152e/64`
  - Náleží do (pod)sítě `2001:0db8:0000:000a::/64`
    - Po vynechání úvodních nul `2001:db8:0:a::/64`
- Koncové sítě mají typicky **prefix /64** (nutné pro SLAAC), organizace dostává /48 nebo /56

---

# Typy IPv6 adres

- **Individuální** (*unicast*)
  - Identifikují právě jedno síťové rozhraní
  - Data se doručují tomuto rozhraní
- **Skupinové** (*multicast*)
  - Identifikují celou skupinu síťových rozhraní
  - Data se doručují všem členům skupiny
- **Výběrové** (*anycast*)
  - Identifikují celou skupinu síťových rozhraní
  - Data se doručují nejbližšímu členovi skupiny

---

# Globální individuální IPv6 adresy

- **Global Unicast Addresses**
- Adresy ze sítě **2000::/3**
- Obdoba **veřejných IPv4 adres**
  - Jednoznačná identifikace rozhraní v rámci celé sítě internet
  - Přiřazovány automaticky pomocí SLAAC (router advertisement), DHCPv6 nebo manuálně
  - Identifikátor rozhraní: Windows generuje náhodně (ne z MAC adresy) a navíc používá dočasné adresy

# Speciální IPv6 adresy

- **Neplatná** IPv6 adresa
  - 0:0:0:0:0:0:0:0 nebo ::
- **Loopback** IPv6 adresa
  - 0:0:0:0:0:0:0:1 nebo ::1
- **Privátní** IPv6 adresy
  - Místní adresy (unique local a link-local adresy)
  - Nesměrovatelné v síti internet
- **Další vyhrazené prefixy**
  - 2001:db8::/32 – dokumentace a příklady (RFC 3849)
  - ::ffff:0:0/96 – IPv4 adresy mapované do IPv6 (např. ::ffff:147.229.178.134)

# Výhody protokolu IPv6 (1)

- **Větší prostor adres**
- **Automatická konfigurace** adres
  - Podpora bezstavové konfigurace (SLAAC, nevyžaduje DHCP)
- **Zabezpečení** na úrovni sítě
  - IPsec (Internet Protocol Security) je součástí architektury IPv6
  - Historie: do roku 2011 povinný (MUST) pro každou implementaci, od [RFC 6434](https://www.rfc-editor.org/rfc/rfc6434) jen doporučený (SHOULD) – potvrzeno i v aktuálním [RFC 8504](https://www.rfc-editor.org/rfc/rfc8504) (2019)
- Podpora **QoS** (Quality of Service)
  - Identifikace typu dat v hlavičce (nešifrováno),
  - Flow label
  - V IPv4 DSCP

<!--
RFC 8504 (IPv6 Node Requirements, leden 2019) nahradilo RFC 6434 (2011), které nahradilo RFC 4294 (2006). Aktuální požadavky na IPv6 uzel: IPsec SHOULD, dočasné adresy (privacy extensions) SHOULD s možností vypnutí uživatelem, přechodové mechanismy (6to4, ISATAP, Teredo) nejsou vyžadovány.

# Výhody protokolu IPv6 (2)

- Menší velikost **směrovacích tabulek**

- Menší **fixní velikost hlavičky**
  - Obsahuje jen nejnutnější informace, vše ostatní jinde
- **Eliminace všesměrového vysílání**
  - Nahrazeno skupinovým vysíláním s možností definice dosahu

# IPv6 ve Windows 11 – výchozí chování

- **Dual stack**, výběr adresy podle tabulky prefixů (RFC 6724) – IPv6 má přednost
  - `Get-NetPrefixPolicy`, `netsh interface ipv6 show prefixpolicies`
  - Preferovat IPv4 místo vypínání IPv6: registr `DisabledComponents` = 0x20
- **Náhodné identifikátory** rozhraní a **dočasné adresy** (RFC 8981) zapnuty
  - `Get-NetIPv6Protocol` → `RandomizeIdentifiers`, `UseTemporaryAddresses`
- **Bezestavová konfigurace** (SLAAC) + DHCPv6 podle příznaků M/O v router advertisement
- **Přechodové (tunelovací) technologie** jsou zastaralé a vypnuté
  - 6to4 od Windows 10 1607, ISATAP od 1703, Teredo od 1803 – používat nativní IPv6

# Bezdrátové sítě

- Identifikovány pomocí **SSID** (Service Set Identifier)
  - Různé bezdrátové sítě mohou mít stejné SSID
- Mohou být **neviditelné**
  - Nevysílají své SSID (zakázán tzv. SSID broadcast)
- Nastavení uloženo v (bezdrátových) **profilech**
  - Vytvářeny při připojení nebo importováním z XML (ručně, `netsh`, Intune / zásady skupiny)
  - Uspořádány podle priority profilu (preference sítě)
    - Výše uvedené bezdrátové profily (sítě) mají vyšší prioritu
    - Pokud je v dosahu více bezdrátových sítí, k nimž se systém automaticky připojuje, připojí se k té s nejvyšší prioritou

# Možnosti zabezpečení

- **WEP** (Wired Equivalent Privacy)
  - Prolomený – klíč 40 / 104 bitů (RC4); Windows od 10 1903 při připojení varuje, v budoucí verzi bude připojení odmítnuto
- **WPA** (Wi-Fi Protected Access, TKIP)
  - Dočasná náhrada za WEP během vytváření WPA2; dnes stejně zastaralé jako WEP
- **WPA2** (Wi-Fi Protected Access II, 802.11i)
  - Šifrování AES-CCMP; zranitelnost KRACK (2017) opravena aktualizacemi klientů
- **WPA3** (Wi-Fi Protected Access III, 2018)
  - Osobní režim: SAE (Simultaneous Authentication of Equals) místo PSK – odolné proti offline útoku na heslo, dopředná bezpečnost
  - Povinná ochrana řídicích rámců (PMF), režim WPA3-Enterprise 192-bit, přechodový režim WPA2/WPA3
  - Doplněk Wi-Fi Enhanced Open (OWE) – šifrování i na otevřené síti bez hesla
  - Podpora ve Windows 10 i Windows 11; v pásmu 6 GHz povinné

<!--
WEP používá jen 40 bitů resp. 104 bitů pro klíče, 24 bitů se používá pro uložení dalších informací (IV).
WPA2 je implementací standardu 802.11i.

WPA3 (Wi-Fi Alliance 2018): SAE handshake nahrazuje čtyřcestný handshake s PSK, který byl náchylný na offline slovníkový útok; Wi-Fi Easy Connect (DPP, QR kód) pro zařízení bez displeje. Zranitelnosti Dragonblood (2019) vedly k úpravám SAE (hash-to-element, H2E).

# Režimy protokolů WPA2 a WPA3

- **Osobní** (*personal*) režim
  - Sdílené heslo pro celou síť: WPA2-PSK (klíč 256 bitů odvozen z hesla), WPA3-SAE
- **Podnikový** (*enterprise*) režim – IEEE 802.1X
  - Každý uživatel / zařízení se ověřuje samostatně (EAP), klíč relace se generuje pro každé připojení
  - Vyžaduje autentizační server RADIUS (Windows Server: Network Policy Server) a certifikační autoritu (CA) pro certifikát serveru
  - Metody: EAP-TLS (certifikát klienta, čipová karta, Windows Hello for Business), PEAP-MSCHAPv2 (jméno a heslo – např. eduroam), EAP-TEAP
  - Profily se distribuují zásadami skupiny nebo Intune

# Správa profilů bezdrátových sítí

- **Zobrazení** všech profilů
  - `netsh wlan show profiles`, detail včetně hesla: `netsh wlan show profile name=<profil> key=clear`
- **Odstranění** profilu
  - `netsh wlan delete profile name=<profil>`
  - Nastavení \ Síť a internet \ Wi-Fi \ Spravovat známé sítě \ **Zapomenout**
- **Změna priority** profilu (sítě)
  - `netsh wlan set profileorder name=<profil> interface=<rozhraní> priority=<číslo>`
- **Export / import** profilu (XML) – nasazení na více počítačů
  - `netsh wlan export profile name=<profil> folder=C:\Profily key=clear`, `netsh wlan add profile filename=<soubor.xml>`
  - Centrálně: Intune (konfigurační profil Wi-Fi) nebo zásady skupiny (*Zásady bezdrátových sítí 802.11*)

# Sdílení v síti – co se změnilo (SMB ve Windows 11 24H2)

- Sdílení souborů a tiskáren = protokol **SMB** (podrobně L06); Domácí skupina odstraněna (1803)
- **SMB1** není v žádné edici Windows 11 nainstalován (volitelná funkce SMB 1.0/CIFS); NetBIOS porty (137–139) už nejsou v pravidlech brány firewall
- **Podepisování SMB povinné** ve Windows 11 24H2 (Pro, Enterprise, Education – příchozí i odchozí) a Windows Server 2025 (jen odchozí, tj. jako klient)
  - Klient se nepřipojí k serveru bez podpisu ani přes hosta (*guest*) → typicky starší NAS
  - Edice Home podepisování nevyžaduje
- **Připojení hostem** (*insecure guest*) zakázáno i v edici Pro; **blokování NTLM** pro odchozí SMB; volitelně **povinné šifrování** a minimální dialekt (SMB 3.1.1)
- **Omezovač rychlosti ověřování** (2 s po neúspěšném pokusu) proti hádání hesel
- **SMB over QUIC** – SMB přes UDP 443 s TLS 1.3 bez VPN; server: všechny edice Windows Server 2025 (dříve jen 2022 Azure Edition), klient: Windows 11

# Tisk ve Windows 11 – moderní tisková platforma

- **Windows Ready Print** – vestavěný ovladač třídy IPP (Internet Printing Protocol) pro tiskárny s certifikací Mopria (síť i USB, od Windows 10 21H2)
  - Bez ovladačů výrobce; přizpůsobení přes Print Support Apps z Microsoft Store
- **Windows protected print mode** (WPP) – Windows 11 24H2+, zatím volitelně (v budoucnu výchozí)
  - Nastavení \ Bluetooth a zařízení \ Tiskárny a skenery \ Předvolby tiskárny → *Nastavit*
  - Povolí jen IPP/Mopria tiskárny; tiskárny s ovladači třetích stran se odinstalují (včetně XPS Document Writer a Faxu)
  - Zavaditelné zásadami skupiny / Intune; ovladače třetích stran se nenačítají, spooler běží s nižšími oprávněními
- **Konec servisu ovladačů třetích stran** (v3/v4) přes Windows Update
  - **15. 1. 2026** – na Windows Update nejsou přijímány nové ovladače (Windows 11+, Server 2025+)
  - **1. 7. 2026** – při výběru ovladače má vždy přednost vestavěný IPP ovladač
  - **1. 7. 2027** – přes Windows Update jen bezpečnostní opravy; instalační balíčky výrobců fungují dál
- Protokol **LPR/LPD** zastaralý (od Server 2012) → IPP

# Universal Print – tisk z cloudu

- **Cloudová tisková služba** Microsoft 365 (Azure, Microsoft Entra ID) – náhrada tiskového serveru Windows Server
  - Tiskárny se registrují do Entra tenantu přímo (Universal Print ready) nebo přes **konektor** na počítači s Windows
  - Klient: Windows 10/11 připojený k Entra ID – tiskárny se přidávají v Nastavení \ Tiskárny a skenery bez ovladačů (IPP)
  - Přístup přes skupiny zabezpečení, vyhledání tiskárny podle umístění, správa v Microsoft 365 admin center
  - Součást licencí Microsoft 365 / Windows Enterprise; účtuje se počet úloh (job pool)
- Pro rozšíření staré tiskové fronty: konektor umí sdílet tiskárny s **IPP Class Driver**
- **Alternativy třetích stran**: PaperCut, Printix, uniFLOW …
